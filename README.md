# 清洗剂客户管理（GitHub 存储版）

一个单文件网页应用：客户资料、跟进记录、速记/待办/汇总、图片，全部存在你自己的 GitHub 仓库里。
网页放 GitHub Pages，电脑和手机打开的是同一个网址、同一份数据。

> **重要：仓库必须是公开（Public）才能这样用，这意味着任何知道仓库地址的人都能看到里面的客户资料（公司、联系人、电话）。**
> 如果资料需要保密，请不要用这个方案，改用带登录的私有后端。

---

## 一、准备仓库（约 5 分钟）

1. 登录 GitHub，点右上角 **+ → New repository**。
2. 仓库名随意（例如 `qingxi-crm`），可见性选 **Public**，勾选 **Add a README file**，创建。
3. 进入仓库，点 **Add file → Upload files**，把本目录里的这些文件上传：
   - `index.html`
   - `data.json`
   - `README.md`（可选，仅说明用）
4. 提交（Commit changes）。
5. 图片不用手动建目录：第一次在网页里上传图片时，程序会自动创建 `images/`。

## 二、开启 GitHub Pages（约 2 分钟）

1. 仓库页 **Settings → Pages**。
2. **Source** 选 **Deploy from a branch**，Branch 选 **main**，目录选 **/ (root)**，保存。
3. 等 1～2 分钟，页面顶部会出现网址：`https://你的用户名.github.io/仓库名/`。
4. 打开这个网址就是你的客户管理系统。

## 三、生成 Token（约 3 分钟）

只有填了 Token 才能修改数据；不填就是只读模式（能看不能改）。

1. GitHub 右上角头像 → **Settings** → 左侧最下 **Developer settings**。
2. **Personal access tokens → Fine-grained tokens → Generate new token**。
3. 填写：
   - **Token name**：例如 `qingxi-crm-pages`
   - **Expiration**：按需选择（建议 90 天或自定义，到期需要重新生成）
   - **Repository access**：选 **Only select repositories**，只勾选你刚建的那个仓库
4. **Permissions → Repository permissions**：
   - 找到 **Contents**，设为 **Read and write**（其余保持 No access 即可）
5. 点 **Generate token**，复制以 `github_pat_` 开头的字符串。
   **Token 只显示一次，请立刻保存到安全的地方。**

## 四、首次打开并连接

1. 打开 Pages 网址。
2. 顶部会显示黄色提示「只读模式 · 尚未连接 GitHub 仓库」。
3. 点右上角 **数据 → 云端设置与同步**，填写：
   - GitHub 用户名（例如 `zhangsan`）
   - 仓库名（例如 `qingxi-crm`）
   - 分支：`main`
   - Fine-grained Token：粘贴上一步的 token
4. 点 **保存并连接**。页面顶部变成绿色的「云端已连接」。
5. Token 只保存在这台设备的浏览器里（localStorage），不会写进网页文件，也不会进仓库。

## 五、把现有本地数据搬过来（如果你之前用过本机版）

1. 在旧版页面里先导出：**数据 → 导出 JSON（图片可选）**，得到一个 `.json` 备份文件。
2. 在新页面打开 **数据 → 从 JSON 导入恢复**，选择该文件。
3. 打开 **数据 → 云端设置与同步**，点 **立即上传本地数据**，确认后会把客户、跟进、速记和图片整体写入仓库。

> 如果旧数据只存在旧页面的浏览器缓存里、没有导出过文件：先用旧页面导出一次 JSON，再按上面步骤导入。

## 六、日常使用

- 任何修改（新建客户、写跟进、速记、改图片说明等）会在约 1 秒后自动提交到仓库，commit 信息形如 `更新客户数据 2026-11-27 14:03:22`。
- 顶部绿色条显示上次同步时间；点 **从仓库刷新** 可以手动拉取最新数据。
- 数据文件：仓库根目录 `data.json`（可直接在 GitHub 网页里查看、甚至手动改）。
- 图片文件：`images/<图片ID>.<扩展名>`，网页里显示的是 raw 链接。

## 七、多设备与冲突

- 家里电脑和手机可以同时打开同一个网址。
- 每次保存前程序会先取仓库里 `data.json` 的最新版本号（sha）：
  - 如果仓库已被其他设备更新，本次保存会**停止覆盖**并提示「同步冲突」。
  - 处理办法：点 **从仓库刷新** 拿到最新数据，再重新做这次修改。
- 程序不会静默丢数据：写入失败时本地缓存仍保留修改，顶部红色提示会说明原因。

## 八、手机怎么用

1. 手机浏览器（Safari / Chrome / 微信内置浏览器均可）打开 `https://你的用户名.github.io/仓库名/`。
2. 点 **数据 → 云端设置与同步**，填一次仓库信息和 Token（和电脑上一样的填法）。
3. 建议把网页「添加到主屏幕」，下次像 App 一样打开。
4. 手机上第一次填完 Token 后，只要不清除浏览器数据就一直有效。

## 九、限制与提醒

- **仓库公开**：所有客户资料对能访问仓库的人可见，请自行评估。
- **国内访问**：`github.io` 在国内可能较慢、间歇打不开，必要时自备网络条件。
- **图片体积**：单张图片程序限制 20MB；建议控制在 2MB 以内（先压缩再传）。GitHub 对单文件有 100MB 硬限制，仓库长期建议保持在 1GB 以内。
- **Token 安全**：Token 相当于仓库写权限的钥匙，不要发到群里、不要截图外传；泄露了立即到 GitHub 撤销并重新生成。
- **浏览器清数据**：清除浏览器数据后需要重新填一次 Token（仓库数据不受影响）。
- **只读模式**：没填 Token 时所有修改入口都会提示并打开设置页，不会产生任何写入。

## 十、备份与恢复

- **备份**：GitHub 仓库本身就是完整备份。也可以在网页里 **数据 → 导出 JSON（图片可选）** 下载到本地。
- **恢复**：在仓库历史里找到旧的 `data.json` 版本，点 **Raw → 下载**，再用 **从 JSON 导入恢复** 导入；或在 GitHub 里直接回退该文件的提交。
- **换仓库/换账号**：清除 Token 后在云端设置里改成新的用户名/仓库名即可。

## 十一、文件清单

| 文件 | 作用 |
| --- | --- |
| `index.html` | 整个应用（界面 + 逻辑，单文件无外部依赖） |
| `data.json` | 客户、跟进、速记、图片索引，仓库即数据库 |
| `images/` | 图片文件目录，首次上传时自动创建 |
| `README.md` | 本说明 |
